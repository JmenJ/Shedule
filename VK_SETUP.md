# Пересылка беседы ВК в Telegram

Источник: `2000000012`. Неизвестное содержимое и ошибки переноса вызывают уведомление с `@thelovelesss` и ссылкой на беседу.

## Работа бота

- На сервере используется HTTP: cookies авторизованного аккаунта → временный web-токен → `messages.getHistory` одной заданной беседы. Токен обновляется до истечения срока и один раз после ошибки авторизации API.
- Браузер нужен только для первоначального входа на вашем компьютере. В серверном Docker-образе нет Chromium и Playwright.
- Проверка новых сообщений выполняется примерно каждые 5 секунд. Запросы, скачивание больших файлов и ограничения ВК могут увеличить задержку. Это polling, а не Long Poll.
- Переносятся тексты, фото, документы, доступные прямыми файлами голосовые, аудио и видео, содержимое ответов и пересланных сообщений. Файлы скачиваются потоком, лимит — 45 МиБ.
- При нескольких новых сообщениях история догружается страницами с перекрытием. Если безопасно догрузить всё не удалось, позиция не перескакивает через непрочитанный остаток.
- В группу не добавляются уведомления о подключении, плашки теста или подписи с ID. Неизвестные вложения, опросы и недоступные файлы требуют ручной проверки.
- По умолчанию очередь, cookies и защита от повторов находятся в памяти. Перезапуск очищает прогресс, загруженная история пропускается; сообщения за время простоя могут быть потеряны. PostgreSQL остаётся необязательным вариантом.
- Ничего не публикуется в ВК: HTTP-клиент содержит только запрос выдачи токена и чтение истории. Изменения и удаления уже пересланных сообщений не синхронизируются. Фото отправляются по отдельности.

Протокол недокументирован и может измениться. Источник исследования: [VKBrowserClient](https://github.com/t3chn0pr13st/VKBrowserClient/blob/main/docs/ARCHITECTURE.md). Его C#-код не требуется устанавливать.

## Настройка

1. Существующий Telegram-бот должен находиться в целевой группе и иметь право отправлять сообщения, фото и файлы. `BOT_OWNER_IDS` определяет владельцев, которым доступна `/vk_test`.
2. На своём компьютере запустите `vk_login.cmd`, войдите в ВК и откройте нужную беседу. Пароль и коды вводятся только на сайте ВК. Помощник проверит чтение и сохранит `vk-session-private/vk_auth.json`.
3. В Render → Environment → Secret Files добавьте файл как `vk_auth.json`. Он содержит авторизованную сессию: не отправляйте его в чат и не добавляйте в GitHub.
4. Для существующего сервиса укажите:

   ```text
   VK_RELAY_ENABLED=1
   VK_RELAY_ONLY=1
   VK_RELAY_STORAGE=memory
   VK_RELAY_TRANSPORT=http
   VK_HTTP_POLL_SECONDS=5
   VK_TG_CHAT_ID=-1002624742750
   VK_PEER_ID=2000000012
   VK_REVIEW_MENTION=@thelovelesss
   VK_SESSION_FILE=/etc/secrets/vk_auth.json
   ```

   Используются существующие `BOT_TOKEN`, `BOT_OWNER_IDS`, `WEBHOOK_URL`, `WEBHOOK_SECRET`. В режиме `VK_RELAY_ONLY=1` база расписания не открывается и команды расписания не обслуживаются.

5. Runtime — Docker; запуск `python main.py`, порт `0.0.0.0:$PORT`. Пингуйте `/` внешним монитором как раньше. Новый сервис для этого не нужен.

`render-vk.yaml` — справочный пример нового сервиса. Не создавайте второй постоянный бесплатный сервис только для этого обновления: бесплатные часы общие для рабочего пространства.

## Проверка

На `/` значения `service=vk-relay`, `vk_transport=http`, `vk_relay=reading` означают, что служба запущена и история ВК успешно прочитана. Одного `status=ok` недостаточно для подтверждения доставки. Остальные состояния: `starting`, `needs_login`, `needs_review`, `retrying`, `disabled`.

Команда `/vk_test` в целевой группе или личке бота запрашивает свежую историю и копирует последнее сообщение в целевую группу. Запрос, пришедший во время уже начатого чтения, ждёт следующего запроса истории. Тест не меняет обычную позицию пересылки. Подтверждение запроса показывается только в личке; группа получает только содержимое или сообщение о невозможности переноса.

Логи не содержат текстов сообщений, cookies, токенов, подписанных ссылок и полных ответов авторизации. Проверяйте успешные HTTP-циклы и `/vk_test`; настоящая доставка подтверждается ответом Telegram или сообщением в группе.

## Повторный вход и откат

Если cookies перестали действовать или ВК потребовал подтверждение аккаунта, повторите `vk_login.cmd` и обновите Secret File. Обновление файла на Render требует нового deploy. `VK_SESSION_RESET=1` заставляет новый процесс взять исходную сессию из Secret File; затем переменную можно убрать.

Для возврата к прежней браузерной версии используйте сохранённый предыдущий deploy Render: его Docker-образ содержит Chromium. В локальной разработке браузерный режим доступен после установки `requirements-browser.txt`, Chromium и `VK_RELAY_TRANSPORT=browser`; `VK_REFRESH_SECONDS=120` относится только к нему.

## Локальные проверки

```text
python -m pip install -r requirements-browser.txt
python -m unittest discover -s tests -v
```

`requirements-browser.txt` нужен помощнику входа и тестам старого транспорта. Сервер устанавливает только `requirements.txt`.

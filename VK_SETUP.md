# Пересылка беседы ВК в Telegram

Беседа: `2000000012`. При ручной проверке бот отмечает `@thelovelesss`.

## Что реализовано

- Новые тексты, фото, документы; голосовые, аудио и видео при наличии прямого файла.
- Текст и вложения пересланных сообщений и ответов. История, загруженная при первом подключении, пропускается.
- Опросы и неизвестные вложения: сообщение «Не удалось перенести… Требуется ручная проверка», отметка владельца и ссылка на беседу.
- Недоступный/слишком большой файл: такое же уведомление. Лимит скачивания — 45 МиБ.
- Очередь и прогресс по каждой части сообщения в PostgreSQL. После перезапуска работа продолжается; возможный разрыв истории вызывает уведомление.
- Самостоятельные переподключения, уведомление при потере входа/изменении формата, не чаще раза в час для одного вида ошибки.
- Браузер использует обычную страницу беседы и читает структурированные ответы, которые получает веб-клиент. Свой OAuth-токен VK не нужен. Программа не вводит текст в ВК и блокирует известные запросы отправки/изменения сообщений. Открытие беседы может отмечать сообщения прочитанными.

## Что ещё нужно проверить с реальным аккаунтом

Локальные тесты проверяют обработку сообщений, вложений, восстановление очереди и отказы. Они не доказывают, что текущая веб-версия VK отдаёт совместимый формат, что VK примет сессию с IP Render или что Chromium поместится в 512 МБ вместе с расписанием. Помощник входа проверяет совместимость чтения **до** сохранения файла. Затем нужна проверка на Render.

Для стабильной доставки браузер должен работать непрерывно. Обновления ВК, проверка входа, истечение сессии, рестарты и лимиты бесплатного Render могут потребовать вмешательства. Редкий сбой между успешной отправкой в Telegram и записью результата в базу способен повторить последнюю часть сообщения. Изменения/удаления уже пересланных сообщений не синхронизируются. Оформление автора и альбомов передаётся обычными сообщениями; фото отправляются по отдельности.

## Однократная настройка

1. В нужной группе Telegram должен быть существующий бот расписания с правом отправлять текст, фото и файлы. После выкладки этого кода команда `/myid` показывает и ID группы. Его нужно установить в `VK_TG_CHAT_ID`. Если ID пока неизвестен, сначала выложите код с `VK_RELAY_ENABLED=0`, получите ID, затем включайте пересылку.
2. Нужна постоянная PostgreSQL: используйте существующую внешнюю базу, если она уже подключена через `DATABASE_URL`, либо укажите отдельную в `VK_DATABASE_URL`. На Render локальная SQLite для пересылки запрещена. В бесплатном Render Postgres срок жизни 30 дней — для постоянной работы это временный вариант. Убедитесь, что данные расписания сохранены перед любым деплоем.
3. Распакуйте проект на Windows и запустите `vk_login.cmd`. Войдите в ВК самостоятельно. Откройте нужную беседу и нажмите Enter в окне программы. Если чтение подтверждено, файл находится в `vk-session-private/vk_auth.json`. Файл предоставляет доступ к аккаунту: не отправляйте его в чат, репозиторий или логи.
4. В Render откройте действующий `Shedule` → Environment → Secret Files. Добавьте файл с именем `vk_auth.json`, содержимое возьмите из локального файла. Его путь на сервере — `/etc/secrets/vk_auth.json`. Секрет загружается через панель Render, а не GitHub.
5. Переменные Render:

   ```text
   VK_RELAY_ENABLED=1
   VK_TG_CHAT_ID=<отрицательный ID группы Telegram>
   VK_PEER_ID=2000000012
   VK_REVIEW_MENTION=@thelovelesss
   VK_SESSION_FILE=/etc/secrets/vk_auth.json
   VK_REFRESH_SECONDS=120
   ```

   Существующие `BOT_TOKEN`, `BOT_OWNER_IDS`, `WEBHOOK_URL`, `WEBHOOK_SECRET` и `DATABASE_URL` остаются настройками бота расписания. `WEBHOOK_URL` должен быть задан, чтобы процесс обслуживал HTTP-порт Render. Сохранённая обновлённая сессия хранится также в базе. При ручной замене входа используйте команду ниже.

6. Для установки Chromium и его системных библиотек нужен Dockerfile из проекта. В настройках существующего сервиса измените Runtime на Docker (Settings → Build → Source → Edit); источник — тот же репозиторий. Новый второй сервис не нужен. Команда запуска задана в Dockerfile: `python main.py`. Порт — `0.0.0.0:$PORT`. Пингуйте `/` внешним монитором как раньше.

`render-vk.yaml` — пример для нового объединённого сервиса, **не инструкция создать второй постоянный бесплатный сервис**. Два сервиса 24/7 превысят общие 750 часов в месяц. У каждого бесплатного сервиса 512 МБ: если браузер вызовет нехватку памяти, потребуется больше ресурсов или другой хостинг.

## Проверка запуска

На `/` поле `vk_relay` показывает `reading`, `needs_login`, `needs_review`, `retrying` или `disabled`. HTTP-ответ `status=ok` подтверждает доступность расписания, а не доставку ВК.

После первого успешно распознанного ответа бот пишет в Telegram, что чтение подключено и начальная история пропущена. Проверьте следующее новое сообщение в беседе (писать в ВК для этого не требуется). Убедитесь, что пришли текст и вложения. Если появляется `needs_review`, сообщение с отметкой или нет подтверждения подключения, чтение нельзя считать работающим.

Логи намеренно не содержат текстов сообщений, cookies, токенов, подписанных ссылок и содержимого сессии.

## Обновление сессии

Если VK разлогинил аккаунт, повторите `vk_login.cmd`, обновите Secret File и задайте `VK_SESSION_RESET=1` на один запуск. После успешного подключения уберите эту переменную. Прогресс сообщений при этом не сбрасывается.
